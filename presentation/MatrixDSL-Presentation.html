    01 · The language
    
    
    Shape is the type

    03 · Operator fusion
    
    
    Fuse only when nobody else is watching
    
    
    The fusion pass rewrites a producer–consumer pair into one Tier 2 op — but only when the intermediate value has exactly one use. Fusing a value that something else still reads would force it to be computed twice. These four cases are the pass's full behaviour.

    Head to head
    Verified · mdtsim --perf
    
      
    
      
    The performance model is analytical, not cycle-accurate hardware. It sums a fixed latency table (DRAM 8, scratchpad 1, MATMUL family 4, vector/transpose/relu/reductions 2, scalar 1), then run-length-encodes the trace into Transfer and Compute runs and lets each adjacent pair overlap — costing max(T, C) instead of T + C. It is built for comparing code-generation strategies against each other, not for predicting silicon.

    05 · The target
    
    
    MDT, a machine shaped like the problem
    
    
    MDT (MatrixDSL Target) is a 32-bit load/store ISA with a dedicated matrix register class. It exists as a specification, an assembler, and mdtsim — a C++ simulator that executes it and reports the performance model. There is no physical chip.
    

    
    
      
    Scalar R0–R15
    32-bit. Addresses, loop counters, BF16 conversion.
    
      
    Vector V0–V7
    128-bit, 4 × FP32 lanes. Row results from reductions.
    
      
    Matrix M0–M7
    4 × 4 FP32 = 64 bytes each. The unit of work.
    
    
    

    
    
      
    
        
        
        
      
    
      SCRATCHLOAD/SCRATCHSTORE are pseudo-ops: LOAD/STORE with the address-space bit set. exp is a runtime call, not an instruction.

    06 · Mixed precision
    
    
    BF16: keep the range, drop the tail
    
    
    BF16 is the top half of an FP32: same sign, same 8-bit exponent, only 7 mantissa bits. MDT's CVT.F32.BF16 is literally Rd = Rs & 0xFFFF0000 — storage halves, range survives. Compute stays FP32.     What's actually new here
      
        
    • The language, IR and ISA were designed together — MDT's fused instructions exist because the fusion pass produces those exact patterns.
      • 
        
    • A use-count-guarded fusion pass small enough to read in one sitting.
      • 
        
    • A measurable ablation: same program, with and without scratchpad reuse, compared on instructions, bytes moved and estimated cycles.
      • 
      
    
      
    What this is not
      
        
    • Not MLIR. Tensor IR is a hand-rolled C++ IR, inspired by MLIR's linalg/vector layering.
      • 
        
    • Not cycle-accurate. The cycle numbers come from an analytical model with a fixed latency table.
      • 
        
    • Not hardware, and not a TPU. It borrows ideas real accelerators use — matrix units, software-managed SRAM, epilogue fusion — at teaching scale.

    09 · Questions we expect
    
    
    Viva, answered in advance
    
    
    
      
    Why build your own Tensor IR instead of using MLIR?
    MLIR is the right tool at production scale, but it would take most of the semester to learn its infrastructure. A 19-op C++ IR lets every member read the whole thing. The structure deliberately mirrors MLIR's idea — a tensor-level layer above LLVM where shapes are still visible — so fusion and tiling happen before that information is lost.
    
      
    Are the cycle counts real?
    They are real outputs of our model, not of hardware. mdtsim --perf sums a fixed latency table and applies a transfer/compute overlap rule. The numbers are meaningful relative to each other — naive vs. scratchpad, fused vs. unfused — and not as absolute predictions.
    
      
    Why does fusion check the use count?
    If matmul(A,B) is consumed by relu and also printed, fusing it into MATMULRELU would mean the plain product no longer exists for the print. You'd have to compute it twice. So the pass only fuses when the intermediate has exactly one use — mtxtensorir has a negative test for exactly this.
    
      
    Why a scratchpad instead of a cache?
    A cache guesses what to keep; a scratchpad is told. Because the compiler knows the whole access pattern of a matmul, it can place tiles explicitly and get predictable 1-cycle access. That's the same trade real accelerators make with on-chip SRAM.
    
      
    How does a 256×256 matmul run on a 4×4 matrix unit?
    It's broken into 4×4 tiles: 64 tiles per side, so 64³ = 262,144 tile-level MATMUL/MATMULACC operations. Doing that efficiently — deciding which tiles stay in the scratchpad — is the job of the Review 3 tiling pass.
    
      
    Why is BF16 conversion just a bit mask?
    BF16 was designed as the upper 16 bits of FP32: identical sign and exponent, truncated mantissa. Converting is dropping the low 16 bits; converting back is shifting them in as zeros. Range is preserved, precision drops to about 2–3 significant digits, and MDT still computes in FP32.
    
      
    Where does exp for softmax come from?
    A runtime call, mdt_softmax_exp. The ISA provides what softmax needs around it — MROWMAX for numerical stability, MROWSUM and VREDSUM for the denominator — but a transcendental function isn't worth a hardware instruction at this scale.
